## Summary
- Stood up `node-learning/`, a Node.js + TypeScript practice lab (Jest, tsconfig, npm scripts) with 17 numbered topics progressing from modules and the filesystem through events, streams, async, an HTTP server, an Express API, env/config, error handling, Jest testing, child processes, cluster/worker threads, buffers, crypto, timers/event loop, npm packages, and glob/grep — each topic paired with its own test file.
- Built out the repo's automation scaffolding: the `git-branch-pr` skill (branch/push/PR creation), the `node-tutor` skill for guided lesson generation, the `changelog-writer` subagent, and later the `pr-reviewer` subagent plus the `pr-merge` skill that gates merges on CI status and a current, non-stale review.
- Established process conventions and enforced them at the tooling level: a repo-wide rule that every skill run logs to `logs/<skill-name>/<uuid>.md`, a `changelog/<branch>/<short-sha>.md` entry required per push, and a `.githooks/pre-push` hook that hard-blocks any non-`main` push whose commits don't touch `changelog/`, closing the gap where a changelog entry could be silently orphaned.
- Fixed workflow-ordering and review-driven issues found during real runs: `changelog-writer` was being dispatched after the push instead of before (so its output missed the push it described) — corrected to run pre-push; two issues `pr-reviewer` flagged on its first real review were also fixed.
- Documented the new pre-push hook's one-time per-clone setup (`git config core.hooksPath .githooks`) in `CLAUDE.md` and cross-referenced it from `git-branch-pr`, and added `.gitattributes`/`.gitignore` entries to support the new layout (e.g. keeping `node-learning`'s own ignores and `package-lock.json` in check).
